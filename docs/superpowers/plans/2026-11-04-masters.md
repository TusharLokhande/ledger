# Masters (Categories, Accounts, User Currency) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Categories and Accounts screens (server-paged table + side-panel form, archive/restore) and a per-user currency chosen at sign-up and editable in Settings.

**Architecture:** Two independent features following `src/server/CLAUDE.md` and `src/client/CLAUDE.md`; the only new shared code is a server paging extension and a one-case fallback in `ApplyFilters`. Currency moves from `Accounts` to `Users` and flows to the client through `AuthUserDto`.

**Tech Stack:** .NET 10, EF Core + Npgsql, FluentValidation, Mapster; React 19, react-query, react-hook-form + zod, TanStack Table (`DataTable`), shadcn `ui/`, lucide-react.

**Spec:** `docs/superpowers/specs/2026-11-04-masters-design.md`

## Global Constraints

- No test projects / test files (owner preference). Verify with `dotnet build src/server/Ledger.slnx`, `npm run build` and `npm run lint` in `src/client`, curl, and the browser.
- Not a git repo: no commit steps.
- No new NuGet or npm packages.
- Every query and write scoped to `ICurrentUserService.UserId`; another user's id → `ErrorStatus.NotFound`.
- Services return `Result<T>`; controllers are thin and call `.ToActionResult()`; DTOs via Mapster, never entities.
- Enums `short`-backed, serialized as strings.
- Routes stay in `src/client/src/App.tsx` under `RequireAuth` → `RootLayout`.
- New client features created with `npm run gen <name>`; cross-feature imports only via `index.ts`.
- Dev DB: `docker compose up -d postgres` in `src/server`; API `dotnet run --launch-profile http` in `src/server/Api` (port 5106); client `npx vite` in `src/client` (port 5173). Remember to rebuild before `--no-build` runs.
- Settings helper text, verbatim: "Changing currency only changes how amounts are labelled. Nothing is converted."
- Duplicate messages, verbatim: "A category with this name already exists." / "An account with this name already exists."

## Review Focus

1. Duplicate names differing only by case/whitespace (`"  food "` vs `"Food"`) → rejected as `Duplicate`; renaming a row to its own name is **not** a duplicate (exclude own id). → Task 4/5 verify steps.
2. A random/foreign GUID on GET/PUT/archive/restore → 404, never another user's data. → Task 4/5.
3. Changing a filter, status toggle or page size while on page 3 → table returns to page 1 (no empty page). → Task 7.
4. Category row whose stored icon isn't in the curated list → renders fallback `Circle`, no crash. → Task 7.
5. `authStore.user.currencyCode` missing (session from before this change) or invalid → formatting uses INR, no throw. → Task 6.
